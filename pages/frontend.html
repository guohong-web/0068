① 基础篇

前端基础

前端的工作只有三件事：描述结构（HTML）、描述样式（CSS）、描述行为（JavaScript）。 框架、构建工具、状态管理都是这三件事的放大器。如果这三样不牢，任何框架都只是把问题藏得更深。

🧠
先建立概念地图

前端不是"写页面的技术"，而是在别人的浏览器里运行的程序。读本篇之前，建议先看原理篇的 请求—响应模型（页面是怎么被送到用户面前的）、 渲染模式（CSR/SSR/SSG 的性质与取舍）， 以及术语词典的前端与浏览器分类。 搞清这几个概念，后面的 DOM、虚拟 DOM、构建工具会变得顺理成章。

🎯
本篇学习目标

能脱离教程手写一个响应式页面；能用原生 JS 操作 DOM 并发起接口请求；能说清"输入网址到页面出现"发生了什么。

一、HTML：用语义描述结构

HTML 不是"画页面"的语言，而是"标注内容含义"的语言。浏览器、搜索引擎、屏幕阅读器都依赖标签的语义来理解你的页面。 一个常见误区是全部用 <div> 搭建 —— 能看，但可访问性和可维护性都极差。

标准页面骨架

HTML
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <!-- 移动端必须：否则桌面宽度渲染后再缩放，字会很小 -->
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>页面标题（搜索结果里显示的就是它）</title>
  <meta name="description" content="页面摘要，搜索引擎会展示">
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <header>导航与品牌</header>
  <nav>站点导航链接</nav>
  <main>
    <article>
      <h1>一篇有且仅有一个的主标题</h1>
      <section>
        <h2>章节标题</h2>
        <p>正文段落</p>
      </section>
    </article>
    <aside>侧边相关内容</aside>
  </main>
  <footer>版权与备案号</footer>
  <script src="app.js" defer></script>
</body>
</html>

最常用的标签（覆盖 90% 场景）

标签含义使用要点
h1 ~ h6标题层级每页只有一个 h1；不要跳级（h2 后不要直接到 h4）
p / br段落 / 换行不要用多个 br 制造间距，用 CSS margin
a超链接target="_blank" 时务必加 rel="noopener"
ul / ol / li无序 / 有序列表导航菜单本质是 ul，不要用一堆 div
img图片必须写 alt；加 loading="lazy" 做懒加载
form + input表单每个 input 都要有 label 关联的 for/id
button按钮默认可聚焦、可键盘触发，比 div 加 onclick 好得多
table表格数据只用于表格数据，不要用 table 做页面布局
✅
语义化最大的实际收益

表单可访问性直接影响转化率：label 正确关联后，点击文字就能聚焦输入框，移动端体验显著变好。而搜索引擎抓取时，<main>、<article> 里的正文权重高于一堆 div 里的文本。

二、CSS：布局与样式

CSS 的三大块：选择器决定"改谁"，盒模型决定"多大"，布局模式决定"怎么排"。 现代前端完全可以只用 Flex + Grid 完成所有布局，float 和 position 的复杂用法已经不需要了。

盒模型与 box-sizing

默认情况下 width 只算内容区，加上 padding 和 border 会让元素实际变宽 —— 这是新手最常见的布局错乱原因。 一条全局规则可以永久解决它：

CSS · 建议每个项目先写这段
*, *::before, *::after {
  box-sizing: border-box;   /* width 包含 padding 和 border */
}

:root {
  /* 用变量统一管理设计令牌，改一处全站生效 */
  --brand: #4f46e5;
  --radius: 12px;
  --space: 16px;
}

body {
  margin: 0;
  font-family: system-ui, -apple-system, "PingFang SC", sans-serif;
  line-height: 1.7;
  color: #1a1a1a;
  background: #fff;
}

/* 深色模式：媒体查询 + CSS 变量是最省事的方案 */
@media (prefers-color-scheme: dark) {
  body { color: #e8e8e8; background: #111; }
}

Flexbox：一维排列

适用场景：导航栏、按钮组、卡片内元素垂直居中、等高列。记住"主轴 / 交叉轴"两个概念就够了。

CSS · 五个高频配方
/* 1. 水平两端对齐的导航栏 */
.navbar { display: flex; align-items: center; justify-content: space-between; }

/* 2. 垂直水平居中（最经典的需求） */
.center { display: flex; align-items: center; justify-content: center; min-height: 100vh; }

/* 3. 左侧固定 + 右侧自适应撑满 */
.layout { display: flex; }
.side  { flex: 0 0 260px; }          /* 不放大不缩小，固定 260px */
.main  { flex: 1 1 auto; min-width: 0; }  /* min-width:0 防止内容撑破 */

/* 4. 卡片网格自动换行 */
.cards { display: flex; flex-wrap: wrap; gap: 16px; }
.cards > * { flex: 1 1 240px; }

/* 5. 空间不够时自动换行，且让最后一行左对齐 */
.tags { display: flex; flex-wrap: wrap; gap: 8px; }

Grid：二维布局

适用场景：整页布局、图片墙、表单字段对齐。repeat(auto-fit, minmax()) 是响应式网格的万能公式，一行代码替代一堆媒体查询。

CSS
/* 卡片列表：宽度不足 240px 时自动减少列数，无需媒体查询 */
.grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
  gap: 16px;
}

/* 整页三栏布局：侧栏 | 内容 | 目录 */
.page {
  display: grid;
  grid-template-columns: 260px minmax(0, 1fr) 200px;
  gap: 0;
  align-items: start;
}

/* 移动端降级为单列 */
@media (max-width: 900px) {
  .page { grid-template-columns: 1fr; }
}
⚠️
CSS 优先级与选择器污染

优先级顺序：!important > 行内样式 > ID > 类/属性/伪类 > 标签。写 CSS 时优先使用单层类选择器，避免 div .a .b .c 这种长链 —— 它让样式无法复用，且后期只能靠 !important 打补丁。

大型项目建议引入命名约定（BEM）或使用 CSS Modules / Tailwind 等方案从机制上避免冲突。

三、JavaScript：行为与数据

后端开发者用 JS，前端也用它。入门阶段的核心是：变量与类型、函数、数组方法、对象、异步（Promise / async-await）、DOM 操作。 其中异步是最重要的分水岭 —— 不理解它，就无法理解网络请求。

必须掌握的数组方法

现代 JS 中，for 循环处理数据的场景大部分已被这些声明式方法取代，代码更短且不易出错。

JavaScript
const users = [
  { id: 1, name: '张三', age: 24, active: true },
  { id: 2, name: '李四', age: 31, active: false },
  { id: 3, name: '王五', age: 28, active: true }
];

users.map(u => u.name);                       // ['张三','李四','王五'] 映射
users.filter(u => u.active);                  // 只保留 active 为 true 的
users.find(u => u.id === 2);                  // 找第一个匹配项，找不到返回 undefined
users.some(u => u.age > 30);                  // 是否存在满足条件项 → true
users.every(u => u.age > 20);                 // 是否全部满足 → true
users.reduce((sum, u) => sum + u.age, 0);     // 聚合计算 → 83
[...users].sort((a, b) => a.age - b.age);     // 排序（注意会改原数组，先复制）
users.map(u => ({ ...u, vip: u.age > 30 }));   // 展开运算符生成新对象

DOM 操作与事件委托

DOM 是浏览器把 HTML 解析成的一棵对象树。JS 通过它读取和修改页面。

JavaScript · DOM 与事件委托
// 查询（querySelector 返回第一个，querySelectorAll 返回 NodeList）
const list = document.querySelector('#todo-list');
const input = document.querySelector('#todo-input');

// 创建与插入
function addItem(text) {
  const li = document.createElement('li');
  li.className = 'item';
  li.dataset.id = Date.now();        // 写入 data-id 属性
  li.textContent = text;             // 用 textContent 而非 innerHTML，天然防 XSS
  list.appendChild(li);
}

// 事件委托：只在父元素上挂一个监听器，处理所有子元素点击
// 优点：新增的子元素自动拥有事件，且省内存
list.addEventListener('click', (e) => {
  const item = e.target.closest('.item');
  if (!item) return;                 // 点在空白处直接返回
  if (e.target.matches('.del')) item.remove();
});

// 表单提交：一定要 preventDefault，否则页面会刷新
document.querySelector('#todo-form').addEventListener('submit', (e) => {
  e.preventDefault();
  const v = input.value.trim();
  if (!v) return;
  addItem(v);
  input.value = '';
});

异步：从回调到 async/await

网络请求需要时间，JS 不会停下来等它。下面三种写法是同一件事的演进，理解它们的差别就理解了异步的本质。

JavaScript · 三种异步风格
// ① 回调式（老写法，容易嵌套成"回调地狱"）
fetchUser(1, (err, user) => {
  if (err) return handle(err);
  fetchOrders(user.id, (err2, orders) => { /* 越嵌越深 */ });
});

// ② Promise 链
fetch('/api/users/1')
  .then(res => {
    if (!res.ok) throw new Error('HTTP ' + res.status);
    return res.json();
  })
  .then(user => console.log(user.name))
  .catch(err => console.error('请求失败：', err))
  .finally(() => hideLoading());

// ③ async/await（推荐，同步写法表达异步逻辑）
async function loadUser(id) {
  try {
    const res = await fetch('/api/users/' + id);
    if (!res.ok) throw new Error('HTTP ' + res.status);
    const user = await res.json();
    return user;
  } catch (err) {
    console.error('加载用户失败：', err);
    throw err;                       // 交给调用方处理
  }
}

// 并发请求：Promise.all 等全部完成，比串行快很多
const [user, orders, stats] = await Promise.all([
  fetch('/api/user').then(r => r.json()),
  fetch('/api/orders').then(r => r.json()),
  fetch('/api/stats').then(r => r.json())
]);
🚫
两个必须避免的写法

innerHTML 拼接用户输入：el.innerHTML = '<b>' + userInput + '</b>' 是 XSS 漏洞的经典来源。用 textContent。

用 var 和 ==：统一用 const（默认）和 let（需要重新赋值），比较一律用 ===。

四、浏览器渲染与关键指标

浏览器收到 HTML 后，需要把它变成屏幕上像素。理解这条流水线，才知道 CSS 写在哪、脚本放哪里、为什么会有首屏白屏。

HTML→ 构建 DOM→ 构建 CSSOM→ 合成渲染树→ 布局 Layout→ 绘制 Paint→ 合成 Composite
  • 阻塞渲染CSS 会阻塞渲染；普通 <script> 会阻塞解析。脚本放 body 末尾或加 defer。
  • 重排 Reflow改变尺寸/位置（改 width、加元素）会触发，代价高。批量修改后一次性写入 DOM。
  • 重绘 Repaint只改颜色/背景，代价较低。
  • 合成层transform / opacity 动画可只走合成，不掉帧。动画优先用这两个属性。

三个核心性能指标

指标含义良好阈值
LCP最大内容元素绘制时间（首屏主内容出现）< 2.5s
INP用户交互到页面响应的延迟< 200ms
CLS布局偏移（页面元素乱跳的程度）< 0.1
JavaScript · 用代码采集真实用户指标
// 在真实用户的浏览器里测量，比实验室数据更可信
new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    console.log('LCP:', Math.round(entry.startTime), 'ms',
                '元素:', entry.element?.tagName);
  }
}).observe({ type: 'largest-contentful-paint', buffered: true });

// 布局偏移累计值
let cls = 0;
new PerformanceObserver((list) => {
  for (const e of list.getEntries()) {
    if (!e.hadRecentInput) cls += e.value;
  }
  console.log('CLS:', cls.toFixed(3));
}).observe({ type: 'layout-shift', buffered: true });

避免 CLS 的实用手段：给 <img> 写死 width/height 或 aspect-ratio；字体用 font-display: swap；不要在首屏内容上方插入动态广告位。

五、响应式设计

响应式的核心不是"做两套页面"，而是一套内容在不同宽度下自动重排。移动端优先（Mobile First）是主流策略：先写小屏样式，再用 min-width 逐步增强。

CSS · 移动优先的断点体系
/* 基础样式 = 手机（宽度最小的情况） */
.container { padding: 16px; }

/* 平板及以上 */
@media (min-width: 640px) {
  .container { padding: 24px; }
}

/* 桌面 */
@media (min-width: 1024px) {
  .container { max-width: 1100px; margin: 0 auto; padding: 32px; }
}

/* 内容自适应：图片不溢出容器，文字也不撑破 */
img, video { max-width: 100%; height: auto; }
.long-word { overflow-wrap: anywhere; }

/* 用 clamp() 让字号随视口平滑变化，替代阶梯式断点 */
h1 { font-size: clamp(1.6rem, 4vw, 2.6rem); }

/* 用容器查询做组件级响应式（现代浏览器已支持） */
.card-wrap { container-type: inline-size; }
@container (min-width: 420px) {
  .card { display: flex; gap: 14px; }
}
📱
触屏适配三件事

① 可点击区域至少 44×44 px；② 输入框 font-size 不要小于 16px（否则 iOS Safari 会自动放大页面）；③ 慎用 hover 承载关键信息，触屏没有 hover 状态。

六、与后端通信：请求与跨域

前端拿到数据的方式基本只有 fetch。理解请求方法、状态码、跨域和鉴权，是打通前后端的关键。

JavaScript · 一个够用的请求封装
const BASE = '/api';

async function request(path, { method = 'GET', body, headers = {} } = {}) {
  const opts = { method, headers: { ...headers } };

  if (body !== undefined) {
    opts.headers['Content-Type'] = 'application/json';
    opts.body = JSON.stringify(body);
  }

  // 用 Cookie 携带会话时需开启；用 Bearer Token 则从 localStorage 读取
  opts.credentials = 'same-origin';
  const token = localStorage.getItem('token');
  if (token) opts.headers.Authorization = 'Bearer ' + token;

  const res = await fetch(BASE + path, opts);

  // 401 统一处理：token 过期，跳登录
  if (res.status === 401) {
    localStorage.removeItem('token');
    location.href = '/login?next=' + encodeURIComponent(location.pathname);
    return null;
  }

  const data = res.status === 204 ? null : await res.json().catch(() => null);
  if (!res.ok) throw new Error((data && data.message) || ('HTTP ' + res.status));
  return data;
}

// 使用
const users = await request('/users?page=1');
await request('/users', { method: 'POST', body: { name: '张三' } });
await request('/users/1', { method: 'DELETE' });

跨域（CORS）为什么会出现

浏览器有同源策略：协议、域名、端口三者任一不同即为跨域，默认禁止读取响应。这是浏览器行为，不是服务器拒绝了请求（请求其实发出去了）。

方案做法适用场景
后端加响应头Access-Control-Allow-Origin 等接口开放给指定前端域名，最正规
反向代理Nginx 把 /api 转发到后端服务生产环境首选，同源且无需 CORS
开发代理Vite server.proxy 转发本地开发模拟线上同源
JSONP用 script 标签绕过仅 GET，已是历史遗留方案
JavaScript · vite.config.js 开发代理
import { defineConfig } from 'vite';

export default defineConfig({
  server: {
    port: 5173,
    proxy: {
      // 前端请求 /api/users → 实际转发到 http://localhost:3000/users
      '/api': {
        target: 'http://localhost:3000',
        changeOrigin: true,
        rewrite: (p) => p.replace(/^\/api/, '')
      }
    }
  }
});
⚠️
带 Cookie 的跨域请求

若使用 Cookie 鉴权，前端必须设置 credentials: 'include'，后端必须返回 Access-Control-Allow-Credentials: true，且 Allow-Origin 不能是 *，必须写明确域名。同时 Cookie 要设 SameSite=None; Secure。这也是"生产环境更推荐反向代理同源部署"的原因 —— 少一堆配置坑。

当页面超过三五个文件，就需要工具链解决：模块化、语法降级、代码压缩、热更新。现代方案已经很简单。

包管理器：npm / pnpm / yarn

  • npmNode.js 自带，够用。用 npm ci 在 CI 中按 lock 文件精确安装。
  • pnpm磁盘占用小、安装快，多个项目共享依赖。大项目推荐。

📌
关于 lock 文件

package-lock.json / pnpm-lock.yaml 必须提交到 Git。它锁定了每个依赖的确切版本，是"本地能跑、线上也能跑"的保证。只在 package.json 里写 ^1.2.3 而丢掉 lock 文件，某天依赖发新版就会直接构建失败。

八、框架怎么选

框架解决的核心问题是：状态变化时如何高效更新 DOM。原生写法需要手动找到元素再改，框架让你只描述"数据长这样，界面就长这样"。

Vue 3：中文文档质量极高，模板语法贴近 HTML，上手曲线最平缓。国内生态与招聘友好。

Vue · 计数器组件
<script setup>
import { ref, computed } from 'vue';

const count = ref(0);                      // 响应式状态
const double = computed(() => count.value * 2);
</script>

<template>
  <button @click="count--">-</button>
  <span>{{ count }}（两倍：{{ double }}）</span>
  <button @click="count++">+</button>
</template>

<style scoped>
span { margin: 0 10px; font-variant-numeric: tabular-nums; }
</style>

React：生态最大、岗位最多，全部用 JavaScript 表达（JSX）。概念上更"函数式"，学习曲线略陡。

React · 同一个计数器
import { useState, useMemo } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);
  const double = useMemo(() => count * 2, [count]);

  return (
    <div style={{ display: 'flex', gap: 10, alignItems: 'center' }}>
      <button onClick={() => setCount(c => c - 1)}>-</button>
      <span>{count}（两倍：{double}）</span>
      <button onClick={() => setCount(c => c + 1)}>+</button>
    </div>
  );
}

不是所有页面都需要框架。内容型站点、后台表单少的小工具，用原生 JS + Web Components 或 Alpine.js / htmx 反而更轻、更快、更好维护。

原生 · 用模板标签写组件
<!-- 定义在 HTML 中，浏览器原生支持，无需构建 -->
<template id="user-card">
  <style>
    :host { display: block; border: 1px solid #e5e7eb; border-radius: 10px; padding: 12px; }
    .name { font-weight: 600; }
  </style>
  <div class="name"></div>
  <div class="age"></div>
</template>

<script>
class UserCard extends HTMLElement {
  static get observedAttributes() { return ['name', 'age']; }
  constructor() {
    super();
    this.attachShadow({ mode: 'open' })
      .appendChild(document.getElementById('user-card').content.cloneNode(true));
  }
  attributeChangedCallback() {
    const r = this.shadowRoot;
    r.querySelector('.name').textContent = this.getAttribute('name') || '';
    r.querySelector('.age').textContent = (this.getAttribute('age') || '') + ' 岁';
  }
}
customElements.define('user-card', UserCard);
</script>
