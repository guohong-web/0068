学习路线图

网站开发本质上只有三件事：把数据存起来、按规则取出来、漂亮地展示给用户。 下面五个阶段建议按顺序走，但不必等前一阶段"学完"再进下一步 —— 越早把一个完整项目跑通，学得越快。

  1. 阶段零：先建立概念地图（3～5 天）

    不写代码，先把「网站是怎么工作的」搞清楚：请求—响应模型、网络分层、HTTP 协议的性质、并发与进程、无状态与身份识别、分层与耦合、CAP 与一致性。这些是后面所有技术的共同地基，先读一遍能省下后期无数次的困惑。

    进入原理与概念篇 → · 随时查阅专业术语词典 →

  2. 阶段一：前端基础（1～2 个月）

    HTML 描述结构、CSS 描述样式、JavaScript 描述行为。目标是能不看教程手写一个响应式静态页面，理解浏览器渲染流程与 DOM 事件模型。

    进入前端基础篇 →

  3. 阶段二：选择一门后端语言（2～3 个月）

    Node.js / Python / Java / Go / PHP / C# / Rust / Ruby 任选其一。先掌握「HTTP 请求 → 路由 → 查数据库 → 返回 JSON」这条链路，再谈框架。

    看八种语言对比与示例 →

  4. 阶段三：数据库与搭建思路

    关系型数据库（MySQL / PostgreSQL）是必修课，学会建表、索引、事务、连表查询。然后理解分层架构、API 设计、鉴权与工程目录组织。

    看搭建思路 →

  5. 阶段四：把项目部署到公网

    买域名 → 解析 DNS → 买服务器 → SSH 登录 → 装运行时 → Nginx 反向代理 → 配 HTTPS。进阶用 Docker 与 CI/CD 把部署变成一条命令。

    看部署思路 →

  6. 阶段五：运维与长期可用

    上线只是开始。监控、日志、备份、安全加固、性能优化、故障排查 SOP，决定你的站点能不能活过第一年。

    看运维思路 →

💡
唯一真正有效的学习方式

不要"学完再做"。从第一天起就给自己定一个可交付的项目（个人博客 / 记账工具 / 订单系统），每学一个知识点就往上加一块功能，三个月后你会得到一个能写进简历的作品。

一次请求都经过了什么

理解下面这条链路，你就理解了整个 Web 开发的工作范围。任何一个环节出问题，用户看到的就是"打不开"。

浏览器→ DNS 解析→ CDN / TLS→ Nginx→ 应用服务→ 缓存 Redis→ 数据库↩ JSON 响应→ 前端渲染
Bash · 用一条命令看清链路
# 域名解析到哪个 IP？DNS 有没有生效？
dig +short example.com

# 完整请求过程：DNS、TCP、TLS、首字节耗时
curl -o /dev/null -s -w 'DNS:%{time_namelookup}s TCP:%{time_connect}s TLS:%{time_appconnect}s TTFB:%{time_starttransfer}s 总计:%{time_total}s\n' https://example.com

# 服务端返回的头信息：看 Server、Cache-Control、是否走了 CDN
curl -I https://example.com
🔗
这条链路上的每个名词是什么？

DNS、TCP、TLS、反向代理、CDN、会话、缓存……这些词的确切含义与"为什么存在"， 在 专业术语词典 里都有单独词条； 想知道它们背后的原理（比如为什么需要三次握手、为什么 HTTP 是无状态的），请看 原理与概念篇。

从 0 到 1 的完整流程

下面是一个真实项目（以"团队任务管理系统"为例）从需求到上线后稳定运行的完整时间线。注意开发和运维并非前后关系，而是从第二天就交错进行的。

  1. Day 1｜需求与原型

    写下 3～5 个核心用户故事（"作为成员，我能创建任务并指派给同事"）。用 Figma / 即时设计画低保真原型，确定页面清单。不要在这一步纠结配色。

  2. Day 2｜技术选型与仓库初始化

    确定后端语言、数据库、部署方式。创建 Git 仓库，写好 .gitignore、README.md、环境变量示例文件 .env.example，约定分支策略（main 保护 + feature/*）。

  3. Day 3～5｜数据库设计

    先画 ER 图（实体关系图），再写建表 SQL。把用户、任务、项目、评论等实体和它们的关系定清楚。此时改表成本最低，后改代价极大。

  4. Day 6～10｜后端接口开发

    按 RESTful 风格实现接口，先保证能用 curl 调通。同时写好参数校验、统一错误响应、JWT 鉴权中间件。用 Postman / Bruno 保存接口用例。

  5. Day 11～18｜前端页面开发

    先做静态页面还原，再接接口。封装统一的请求层（axios 拦截器）处理 token 与错误提示。做到列表、表单、详情三件套完整可用。

  6. Day 19～21｜本地跑通 + 首次部署

    买域名和服务器 → 装 Docker → 写 docker-compose.yml → 配置 Nginx 反向代理 → 申请 HTTPS 证书。目标：能在手机 4G 网络下打开自己的网址。

  7. Day 22～25｜自动化与监控

    接入 GitHub Actions：推送代码自动跑测试、构建镜像、SSH 部署。装上 Uptime Kuma 做可用性监控，接入 Sentry 收集前端报错，配置数据库每日自动备份。

  8. 上线之后｜迭代与演练

    每周看一次错误率与慢接口；每月做一次备份恢复演练和依赖安全升级；每次发版都准备好回滚方案。

贯穿全站的六条原则

1. 先跑通，再优化

一个能上线的丑网站，胜过一百个躺在本地目录里的完美设计。

2. 一切进版本控制

代码、配置模板、部署脚本、数据库迁移文件都要进 Git。密码和密钥永远不进。

3. 环境一致

用 Docker 或容器化手段消除"我这里能跑"。开发、测试、生产用同一份镜像。

4. 默认不信任输入

所有来自客户端的数据都要校验。SQL 参数化、输出转义、密码哈希，缺一不可。

5. 可观测优先

看不见的系统无法维护。日志、指标、链路追踪要在项目初期就埋点，不能事后补。

6. 假设一定会挂

磁盘会满、内存会泄漏、证书会过期。为每种情况准备预案，并定期演练。

常见问题

我该先学前端还是后端？

没有强制顺序，但推荐先摸前端：它的反馈最快，写一行代码就能在浏览器里看到结果，容易建立正反馈。学到能写静态页面和简单交互（大约 2～4 周）后，立刻转后端，然后做一个前后端都自己写的完整项目。

如果目标是后端/运维方向，前端学到"能看懂、能改"即可，不必追求精通 React 全家桶。

需要学多少种语言？

一门精通 + 一门会用就够了。语言的语法一周就能上手，难的是生态、并发模型和工程习惯。推荐组合：JavaScript（TypeScript）+ Python；或 Java + JavaScript。

不要因为"Go 性能好"就在没写过任何项目的时候去学 Go。性能和并发是解决特定问题的工具，不是入门门槛。

服务器一定要买吗？免费托管够用吗？

静态站点（博客、文档、落地页）完全可以零成本：Cloudflare Pages、Vercel、GitHub Pages 都提供免费托管 + 免费 HTTPS，还自带全球 CDN。

但只要有服务端逻辑、数据库、定时任务，就需要一台真正的服务器。入门级云服务器每月几十元，或者用云平台免费额度起步。建议早期就买一台最便宜的服务器动手练，因为部署和运维的坑只能真机踩出来。

Docker 是必须的吗？

不是必须，但强烈建议。它解决三个具体问题：环境一致性（本地和生产一致）、依赖隔离（不同项目不同版本互不干扰）、部署原子性（一条命令完成发布与回滚）。

如果只是跑一个简单的 Node 应用，用 systemd 或 PM2 也完全可行。等你有两个以上服务时再上 Docker Compose。

网站被攻击了怎么办？

按这个顺序处理：先止损（切流量、加防火墙规则、必要时下线）→ 保留现场（导出日志和快照，不要急着删）→ 定位来源（是 SQL 注入、弱密码、依赖漏洞还是配置错误）→ 修补并加固 → 复盘写进 checklist。

日常预防见运维思路 · 安全加固章节。

多久能独立上线一个项目？

每天投入 2～3 小时，大约 3～4 个月可以独立完成一个带用户系统、数据库和后台管理的中小型项目并部署上线。全职投入大约 6～8 周。

关键变量不是学习时长，而是是否真的动手做了完整项目。只看教程不动手，一年也上不了线。
